# 规范化图鉴与纯 Go 官方更新：基础实现记录

> **现行v2关系结构与逐项选择/记忆规则，请阅读[图鉴v2说明](<D:/echoagent/MeowNyx Wiki/docs/catalog-v2-choices.md>)。** 下文保留基础实现阶段的设计记录；其中schema1、单一父链及未加入choices的旧接口示例已由v2契约替代，不是当前操作步骤。

## 本期范围

- 官方数据源：<https://static.gamecenter.qq.com/xgame/roco-kingdom/compendium/d.json>。来源解析、差异合并、下载、校验、提交全部在 Go 中完成，不调用 Python、Node、CMD，也不下载并执行远程脚本。
- 数据更新页：检查 → 差异预览 → 确认应用；支持阶段进度、取消检查、失败重试、离页后返回查看同一任务。应用后由用户明确点击重新载入，不自动刷新丢失其他表单草稿。
- 维持既有四个手工页签。本期不增加既有主技能编辑、图片管理或版本管理界面。
- 不新增重量、蛋组、性别比、身高、背景简介、称号、地点、异色或学习/进化等级。现有赛季、机制词条、属性克制、别名和特殊等级占位保留。
- 腾讯接口、资料完整性或游戏机制变更仍可能需要更新 Go 程序。抓取失败、未知结构和缺失字段不是空数据，不会因此删除现有资料。

## 唯一资料与兼容视图

主资料为 [catalog.json](../data/catalog.json)，`schema_version:1`。四份旧 JSON 不再作为项目或新分发包的第二套真实资料。

| 集合 | 主要内容 |
| --- | --- |
| monsters | 稳定本地ID、名称、图鉴编号、形态/进化、六维、属性ID、特性ID、头像/立绘路径、来源映射、本地补充 |
| skills | 稳定本地技能ID、名称、效果、类别、属性ID、能耗、威力、已知赛季 |
| types | 一份属性定义与有向弱点/抵抗关系；无属性None作为运行时中性项，不伪造其他关系 |
| traits | 按名称＋完整描述区分；同名不一定同效果，使用稳定内容标识 |
| learnsets | 每只精灵明确own/inherit/from_id；技能ID＋来源，数组保序，保留传说来源 |
| skill_rules | 已有基础连击和特殊公式标识；其他已审阅计算仍由现有规则模块负责，不从文字猜公式 |
| extensions | 未识别本地字段和必要兼容补丁，不是复制整份旧记录 |

- 官方图鉴ID、游戏协议ID和本地ID是不同命名空间。本地ID不重新编号，来源放`source_ref`，保留现有收藏/编队/技能累计引用。
- 旧名称分隔符、罗马数字以及四个冬季裸名条目已经明确归属，不能通过图片文件名推断身份。
- 头像与详情立绘分开；同一内容可共用资源，但不将不同用途强行合并。
- 精灵原有长特性补充若只在本地存在，与官方摘要拆开保存为`_trait_notes`兼容扩展；界面明确标为本地补充，不能冒充官方原文。
- `default_legacy_type`的重复副本、无生产读取的旧偏好/潜力/状态展开退出核心资料，原始文件保存在项目外迁移备份。

Go主程序通过`GET /api/catalog/data`一次返回同版本的四个内存兼容视图及`revision`。现有页面仍能使用原字段，不必各自解释官方结构。静态预览由 [catalog-data.js](../js/catalog-data.js)投影**本地schema**，不是 JavaScript 官方抓取适配器；Go/JS投影有全量一致性测试。

Node审计使用 [只读helper](../scripts/lib/catalog-data.js)。旧写入脚本仅适用于旧版隔离资料；canonical存在时 [Wiki写入库](../scripts/lib/wiki-data.js)拒绝写入，不能创建看似更新成功但实际不生效的影子文件。

## 合并规则

1. 已验证完整名称/形态和图鉴编号后，普通资质、属性、特性及主技能参数以腾讯来源为准。数值0、明确空值和字段缺失分别处理。
2. 不按相同数字ID、同一头像或去掉形态的基础名合并。来源变更或身份不明的条目列为待核对，保留本地并跳过冒险改动。
3. 本地独有精灵完整保留。本地独有主技能列为待确认，不自动删除。
4. 按2026-10-30用户确认，可靠对应、完整有效且非空的学习集合以官方为准；移出的旧关系保留在变更预览和外部备份中，不删除主技能。先纠正own父表，再比较有效继承集合：一致则保留inherit，实质不同只将该条改为own。保留仍有效的本地传说分类，不另加同技能默认副本；明确的血脉/技能石关系独立。未映射、缺失、空或冲突来源不能清空本地学习面。
5. 普通手工值后续仍可被官方更新覆盖，预览先列出差异；手工值不是永久锁。特殊威力保留项另按已审阅规则保护。
6. 魔能爆能量表、彗星血量比、鸣沙陷阱物防差、闪击速度差及原有不定威力显示不由普通威力字段抹掉。真实语义变化会让未复核快捷规则安全停用；仅排版空白不视为机制改变。
7. 游戏规则与统计完整性不从文字臆测。新状态、永久成长触发、技能替换或协议ID仍需明确实现与验证。

## 更新任务与保存安全

API（固定同源JSON，不接收任意源URL或命令）：

- `GET /api/catalog/update/status`
- `POST /api/catalog/update/check`：`{}`
- `POST /api/catalog/update/cancel`：`{task_id}`
- `POST /api/catalog/update/apply`：`{task_id,base_revision,acknowledge_reviews}`

`checking/preview/applying/applied/cancelled/error`状态明确区分。`blocking`阻止应用；`review`需用户阅读并确认保留未解决项。失败响应不是成功；预览本身不写资料。

- 仅允许固定腾讯HTTPS目录，禁任意代理/凭据URL/跨源重定向，限制响应大小、并发和超时；来源名称/描述拒绝HTML注入。
- 后台任务在页签切换后继续存在，但程序退出时取消非提交阶段或等待安全提交结束；不承诺重启后断点续传。
- 图片普通PNG/JPEG需校验格式、完整解码、尺寸、体积和哈希；只补缺或使用更大尺寸的普通立绘，不因来源更新而强制降图。同尺寸也不宣称更高清。已有裁切头像不被全身立绘替换；新条目无头像时才可使用已验证来源图片补缺。
- 图片失败保留旧图，新条目允许明确缺图。下载未完成、取消或网络失败不会把活动资料改到一半。
- 手工表单与更新预览携带**实际已加载**的`base_revision`。其他编辑已提交时旧请求报冲突，不能借后台status的新版本绕过保护。
- 手工表单先在隔离临时投影上执行已有身份/技能保护，再规范化并走同一版本事务。仅允许明确类型字典引用，不用名称猜未知ID。

## 运行目录、首次迁移与恢复

运行时不要求安装目录可写：

```text
固定用户配置根/小黑猫Wiki/
  catalog/
    current.json             # 唯一活动指针
    previous.json            # 上一有效指针
    versions/<sha256>.json   # 不可变完整资料版本
    images/<sha256>.png      # 不可变已验证图片
  catalog-backups/           # 发行版默认图鉴备份
```

个人配置文件、战报SQLite和编队/收藏不属于图鉴导入，不能被覆盖或清空。开发构建的备份继续使用已约定的项目外`data-updates/runtime`。

- 首次升级若发现完整旧四JSON，即使新包已有canonical，也先保留旧本地资料作为基线，备份原始字节后固定到用户目录；不冒险把旧自建记录与新包同ID记录合并。之后用户点击官方检查来更新普通资料。
- 已有活动版本时不重复导入安装目录遗留JSON。旧文件只存在一部分或损坏时，明确报错，不静默丢弃本地资料。
- 完整数据和图片先写不可变对象并同步；持久备份旧版后，最后用Windows原子替换切换小指针。不是逐个覆盖多个JSON。
- 活动版本损坏时尝试上一有效版本，并保留损坏原件；没有有效恢复版本或碰到未知未来schema时拒绝猜测重置。备份失败阻止提交。
- 本期没有新增手工回滚管理页。需要恢复时，应在关闭程序后保留当前文件，使用经过校验的备份与版本指针恢复；不要混搭不同版本的四份旧JSON。

隔离开发可显式设置绝对路径`XHM_CATALOG_ROOT`和`XHM_CATALOG_BACKUP_ROOT`；测试必须使用临时目录，不能指向真实用户资料。

## 本次来源校对记录

本次源快照含621个详情、466个列表条目、579个技能定义。2026-10-30用户已确认12组历史名/形态对应与3个独立新增：现有622只本地精灵，其中621只对应来源，仅冥古龙619测试占位未映射并完整保留。旧619个ID全部保留，3条新增ID为620–622。

已确认的冬天四形态采用“本来的样子”，甜甜/加油蟹/黑化加尔采用明确形态标签；新月鸷/月辉鸠/月使鸷纳/斑鱼采用新月鹭/月辉鹭/月使鹭纳/玳龟正式名，旧名保留为别名。烈焰狂战士620为独立首领；满月砣上弦621、下弦622分别独立，阶段因源缺失暂记“未确认”，不编造有向进化前置。图鉴提供单独“阶段未确认”筛选。原待审阅表是确认前快照，不再代表这些身份仍在等待决定。

更新页面顶部和底部都有“应用可更新内容”，真正review确认框紧邻按钮；灰色时旁边显示具体原因。阶段缺失、自引用进化列表等固定保留警告默认折叠，展开可看详情，不提供把官方空字段强写进资料的二选一控件，也不阻止其他安全更新。

已复核的普通参数例：逆袭威力100→55且能耗3→1；翅刃95→85且能耗4→3；齿轮扭矩基础80→70、明确永久增长步长20→15；回收物攻→魔攻。血契、鸩毒等新文字已更新，但原本未建模的条件仍手动处理，不凭描述新增模拟。

兽花蕾和陨星虫的本地特性明细保留为带来源标记的补充。热成像家族只增加句号的描述已复核，不改变100%效果。特殊四技能的输入/分档/差值行为有专门回归。

# 共享个人配置与便携版

## 范围与位置

同一 Windows 账户下，支持共享配置的新版本统一使用 `%AppData%/小黑猫Wiki/user-config.json`。路径不包含安装目录、EXE文件名、版本号或HTTP端口。便携版移动/删除程序目录不会顺带清除此文件。不同 Windows 账户的 AppData 相互独立。

共享内容：

- `settings`：窗口、字体、默认页面、缩放、有效种族速度模式/门槛等设置。游戏描述不再作为默认启动选项，旧值读取时回退精灵图鉴；导航入口仍可使用。
- `data.rk_pet_configs`：按稳定精灵ID保存个人性格/个体，不与编队配置混为一份。
- `data.rk_speed_pet_priority`：每速度档位的头像优先顺序。
- `data.rk_speed_form_overrides`：速度页形态选择。
- 速度页个体/性格/精灵列开关、加成、搜索、选中行列改为仅内存。`data.rk_speed_view`是历史字段，新客户端不读取、写入或导入；旧文件中的未知/历史值保留，不借此删除用户其它记录。
- `data.rk_damage_selection`：选择ID及编队入口ID；冷启动恢复最后攻击方，首次无记录留空，不强制221。防守方冷启动固定木桩9001（旧defender字段兼容保留），当次切页不重置。编队入口恢复仍读取对应编队，不写成个人配置。
- `data.rk_damage_skill_configs`：按精灵ID保存完整人工技能记忆。
- `data.rk_damage_view.skill`：最后活动技能快照，包含名称/类型/属性、基础威力、固定/百分比加成、BUFF、连击、减伤、防御修正、星陨和手动最终威力。活动派生值不覆盖每精灵人工技能记忆。两份技能记忆均支持 `basePowerExpression` 算术文本（最多256字符）；数值basePower保持求和结果。
- `data.rk_chart_workspace.state`：曲线version1分组、当前组、独立个体/性格控件和迁移标志。旧rk_chart_fav_pets仅迁入一次，不读取伤害收藏/个人配置；组内唯一精灵ID，全部组视图去重。保存整份state作为一个原子字段，失败不得乐观采用。内置属性预设仅保存选中标识，不保存其成员列表；成员由当前主资料派生，复制为普通分组才保存当时成员。

游戏主资料（monsters/moves/wiki）和图片不属于这个文件，仍随程序分发。未改造的历史程序不会自动读取新文件，不能宣称所有旧版本已兼容；本次不会修改、迁移或卸载旧安装。

## 读取与迁移

启动先等待通用设置和共享个人配置完成读取，再渲染页面。

- 有效共享文件优先；localStorage仅用于兼容缓存和首次迁入旧记录。
- 现有 `settings.json` 非破坏性迁入，原文件保留。
- 首次从当前 WebView 存储导入个人/速度记录，只有非空的旧记录才发出导入请求；后端只补缺失项，不覆盖共享文件里的已有记录。
- 成功导入后记住迁移状态，不能每次启动都从过时缓存复活已删除的记录。新增技能/曲线分组使用 `legacy_imported_keys` 分组标记，即使旧 `legacy_imported=true` 也只补一次缺失技能记忆；空分组也标记完成，后续其他origin旧缓存不复活记录。升级不覆盖已有非空或显式空记录。
- 旧技能记忆中的减伤/防御修正是字符串（例如 `"0"`），按旧合法格式保留。迁移前除共享JSON外也备份真实WebView Local Storage，以便验证每个技能记录。
- 文件损坏、权限错误、无效结构与文件不存在必须区分。前者报错并拒绝覆盖，不能以默认值假装读取成功。
- 浏览器端旧JSON损坏而共享文件又缺少对应数据时，应提示，不用空对象覆盖旧内容。
- 项目外备份必须包含真实 AppData 记录；备份程序目录不等于备份个人配置。迁移前应退出正在使用该目录的应用。

## 个人配置的0/1状态

`rk_pet_configs[id].mode` 为数字0/1。没有记录等价0，按当前形态基础种族值生成默认。已有记录没有mode仍视为1，哪怕nature/iv是空对象也不能自动补点。恢复默认保存0，旧字段可以保留但不参与当前显示。修改任一个体/性格后保存完整六项显式true/false及0/1/2性格，mode转1，用户取消项不能被默认补回。

默认：生命个体；双攻差≤20配双攻个体，否则较高攻击个体；速度<85另加物防个体。速度<115时比较生命与较高攻击：生命高只配生命正性格；攻击高配较高攻击正性格，双攻差≤20则双攻都配；平手不自动加性格。速度≥115不默认加性格。不限制自由模拟勾选数量，不改变编队配置。

设置有单独的“全部精灵个人配置恢复默认”按钮。只有用户点击并确认才发送 `POST {reset_pet_defaults:true}`；与其他操作互斥。服务端锁内读取最新全部个人记录，只设mode0，保留历史iv/nature及未知字段，不改任何技能/编队/曲线分组。写前备份，失败可重试。成功后客户端发 `petdefaultsreset`，活动个人来源重新取默认，编队来源不受影响；仅打开设置或升级不会自动执行。

另一个独立按钮“清空所有精灵配置”发送 `POST {clear_pet_configs:[当前全部精灵ID]}`，包含木桩。与其它写操作互斥；后端合并当前目录ID与所有已保存个人ID，逐项设六个体false、六性格0、mode1，保留未知字段，不删除记录。这样未曾配置的精灵也不会再次自动补默认。成功事件 `petdefaultsreset` 的 `detail.operation` 为`clear`，恢复默认则为`defaults`；均可串行排队、失败保留重试。新增按钮/读取设置绝不自动执行这两项批量操作。

## 写入与关闭

`GET /api/user-config` 返回已存个人数据。`POST {patch:{key:{entry:value}}}` 只更新指定分组的指定项，形态覆盖分组的`null`删除该项；其它分组依各自结构校验，不会整份覆盖不相关记录。`POST {import:{...}}` 只补缺失旧记录。

前端 `UserConfig.patch()` 与 `saveSettings()` 返回是否成功的Promise，写请求串行执行。成功响应后才更新持久化缓存；未保存的界面草稿与已提交数据区分。失败显示常驻提示并保留重试队列，不能声称已保存。新设置可替换失败的旧设置提案，不必反复重试无效值。

后端使用锁、写前备份和临时文件原子替换。合并保存时保留不认识的字段；不认识的新主版本格式拒绝写入。设置页“恢复默认”只重置设置分组，不清精灵/速度数据。

`UserConfig.flush()` 等待保存；`requestClose()` 把结果回传原生关闭回调。原生退出应等待写入完成，失败时保持窗口，最小化行为仍照旧。未经正常关闭的强制终止/断电不可能保证最后一个未到达后端的操作落盘，因此错误提示、原子写与备份缺一不可。

## 测试限制

所有写入测试使用隔离临时配置目录。浏览器持久化端到端测试必须先确认服务是测试fixture，不准指向真实8788应用或真实用户AppData。普通布局测试使用模拟/临时配置API；截图日志可以交付，真实个人配置备份不上传。

应覆盖：空缓存读取旧文件、首次导入不覆盖已有值、跨启动/跨端口读取同份文件、并发分组更新不丢记录、删除不被旧缓存复活、保存失败重试、损坏JSON拒绝覆盖、未知字段保留、恢复默认不删个人记录、关闭时有待保存操作。

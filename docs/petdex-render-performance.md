# 图鉴高阶筛选性能修复

## 复现与实际瓶颈

取消“高阶形态”，在没有其它筛选、地区形态未展开时，当前资料从203行增加到506行。旧实现每次重建tbody的所有行、重新绑定行事件，随后全局游戏词条组件处理所有新增节点。

旧词条队列对每个新节点与已有待处理节点两两做contains检查，批量表格插入时产生平方级额外开销。图鉴设置getter本身只读内存，并没有逐行解析完整个人配置。

在隔离浏览器中，临时停用旧词条组件后，旧表格取消高阶的耗时降至约105—117ms；正式修复没有停用该功能，而是消除重复处理。

## 修复措施

- `petdex.js`：按精灵稳定ID复用tr、头像和未变化的特性节点；仅构建未访问的行，按实际字段变化更新相应单元格。
- 表格统一委托点击，形态/特性按钮不再为每次重建重复绑定。
- 筛选只移出不匹配行，批量插入新增或需要调整顺序的行；正确顺序的现有行保持连接。
- 保留完整506行，不分页、不截断、不固定行高；地区形态、长特性展开、搜索、排序、排名、梦境投影仍工作。
- 缓存只在当前页面内存中，随页面销毁释放；源资料原地修改/删除/隐藏时按字段与ID更新和清理。
- `game-glossary.js`：O(1)加入待处理集合，帧边界按祖先去重，不再做批量兄弟节点两两比较；合并描述区域，保留已装饰且未变化的区域，跳过重复遍历/分词。
- 可见性变化只检查悬停层位置/关闭状态，不扫描所有特性。新增文字、外部改写、编辑区资格变化仍正常触发识别。
- 不修改真实个人配置、不清缓存、不增加本地表格缓存文件、不取消保存/重试/备份保护。

## 同机隔离测量

测试文件位于本轮外部备份中的`petdex-benchmark.browser.js`，记录真实页面点击、同步处理时间以及两帧后的更新耗时。每种情况20次取消、20次重新勾选；首次与后续分开。每种配置均从独立导航重载，核实实际已加载记录数量。

|---|---:|---:|---:|---:|---:|---:|

## 回归

`tests/petdex-render-performance.browser.js`覆盖完整结果集、行/词条节点复用、零重复构建和分词、鼠标/键盘词条悬停、编辑资格改变、形态/特性展开、梦境与有效种族值排序、退出清理和多次重新进入的缓存/监听数。新增仪表仅存在于测试闭包，不暴露生产全局调试状态。

基准使用已有检查版作修复前对照、当前源码作修复后对照。历史备份只用于还原/核验，不作为当前构建输入。最终检查版已做同套功能回归与性能复核：普通配置首次取消88.7ms、后续中位66.5ms（P95 70.9ms）；大记录量首次80.8ms、后续中位66.7ms（P95 91.7ms）。源码和检查版分别完成36组2508项浏览器检查，Node509项及Go test/vet通过。

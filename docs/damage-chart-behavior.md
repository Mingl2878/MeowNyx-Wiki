# 伤害计算与曲线：已确认的行为约定

## 不要为了去重而改变计算用途

两个页面来自软件合并，但部分差异是有意设计，并非缺陷。

- `js/battle-math.js` 统一种族值/个体/性格换算、威力加成、BUFF倍率、普通伤害的逐步取整及特殊威力分段。
- `RKData.getPetStat`、伤害页和曲线页调用公共算术，不另外复制同一份公式。
- 每个页面仍明确选择哪些效果参与计算，不强行使用同一套完整战斗配置。

| 项目 | 伤害计算 | 防御资质曲线 | 攻击资质/威力曲线 |
|---|---|---|---|
| 威力来源 | 手动/技能/记忆/特殊公式 | 伤害页的基础威力与加成 | 曲线数字框或横轴 |
| 本系 | 自动 | 自动 | 曲线本系按钮 |
| 克制 | 按属性自动 | 主线为中性参考；每目标按实际倍率换算等效生命 | 按所选目标实际属性自动 |
| BUFF、连击 | 参与 | 参与 | 保留独立试算，不叠加伤害页设置 |
| 减伤、防御增减益 | 参与 | 不参与 | 不参与 |
| 星陨、手动最终威力 | 参与 | 不参与 | 不参与 |
| 个体、性格 | 当前攻防配置 | 曲线自己的设置，不读取个人配置 | 曲线自己的设置，不读取个人配置 |

不要把上表中的有意排除重新加入曲线。

## 精灵切换、自动覆盖、记忆

- 搜索/历史/收藏选中精灵：模式0或无个人记录时由 `PetConfiguration` 按当前形态种族值生成默认；模式1（含旧版没有mode的已存记录）读取人工性格/个体。手动编辑转1并保存完整显示配置，恢复默认回0，不在渲染时写满全部精灵记录。
- 冷启动恢复最后攻击方（含可用的编队入口）和最后完整技能快照；无攻击方历史时留空，不再指定小黑猫。防守方仅冷启动时回木桩；切页仍恢复当次防守方。有效0威力、手动最终威力、技能名/类型/属性及各修正项都不能被模板初始100覆盖。
- `rk_damage_skill_configs` 保存每精灵的人工技能记忆；`rk_damage_view.skill` 保存当前完整技能状态，含自动派生值。换防守方/自动计算/交换离开时不能用派生值覆盖攻击方的人工记忆。
- 从编队头像进入：使用该编队的配置，不意外套用个人记忆。
- 切换攻击方：恢复目标精灵自己的技能记忆；没有记忆的字段使用默认值，不能继承上一只的残留。
- 机幕方舟保留现有的独立百分比覆盖行为（符合条件25%，其他情况0%），不与手填百分比累加。技能同属性左右切档不清除手动修正；只有对机幕方舟切换为不同技能属性时刷新已有自动加成，精灵切换仍保持原覆盖逻辑。
- 技能选择、自动覆盖与特殊计算全部完成后才保存技能记忆，避免保存成新威力搭配旧类型/属性/名称。
- 滑动条已移除，曲线使用数字框；0是合法威力，不得用 `value || 200` 覆盖。
- 特殊威力继续允许显示和编辑，但自动计算覆盖规则保留。`speed_diff` 比较速度，`phy_def_diff` 比较物防；既有分段数值不变。

## 技能左右键预设

主技能全表逐条审阅，由 `SkillVariants` 以稳定ID及描述/关键字段指纹绑定。左键普通/选择一，右键条件成立/选择二，分别设置单次基础威力与连击。例：驱赶90×1/210×1，爆冲65×1/325×1，筛管奔流80×1/155×1，撕咬20×3/20×5。连击变化不再同时放大单次威力。条件成立是用户选择的模拟档，不自动扣血、回血、加印记、推断天气/历史。用户指定的历史/层数/能耗/队伍/关联技能及若干其它条目，两键都载入基础威力和初始连击，不推测变量。四个未知公式技能及穿膛/背袭/色散按用户明确给定的模拟快捷值处理；图鉴中的不定威力仍显示“?”。灾厄仅右键180，不实现自伤结算。

旧counter倍率与alt总威力不作为单次威力来源。撕咬旧150字段删除；其他资料不擅自改写。百分比档位先按共用BattleMath向下取整，再保留用户独立修正。基础/血脉/过山车图标共用事件事务，完整更新后保存；用户手动最终威力仍优先并保持红色标记。全量审阅、边界及各技能结果见 `skill-variants-audit.md`。

加尔568/黑化加尔569使用固定加法表达式；`basePowerExpression`保存显示，`basePower`保存求和值。按用户确认忽略多次释放的取整差异，合计当一次释放，固定加成、连击、星陨等都按普通算法处理，不额外乘二。手动编辑/普通技能选择清除不匹配表达式；切页/重启保存完整表达式，不把它压成单个数字。专属友谊/驱赶/撒花左右值见审阅表。

## 页面状态与交换

- 切页只恢复界面，不重新选精灵，不重置参数，也不重新执行机幕方舟覆盖。
- 曲线的模式、固定数值、坐标交换、本系选择、对比配置和图例可见性跨页面保留；手动克制选择已移除，不能残留隐藏倍率。
- 曲线个体/性格只来自独立曲线控件，不读取伤害页或个人/编队记忆，也不反向写入。攻击精灵和技能参数仍按原入口带入。
- 伤害页的个体/性格改变不清除曲线设置。分组收藏持久化，旧曲线收藏迁入未分组；不导入伤害收藏。当前/全部组按精灵ID去重，不做多配置头像。
- 攻守交换同时交换精灵、个体、性格和属性显示模式；新攻击方再加载自己的技能设置。
- 固定400线叫“400伤害参考线”；按生命动态计算的线继续称为斩杀线。
- 页面离开通过统一 `onLeave` 清理画布和全局事件；字体/主题/缩放继续使用软件公共系统。

## 等效生命与图形边界

防御资质曲线中，对目标真实HP求最小整数中性伤害n，使 `ceil(n × 实际属性倍率) >= HP`。正倍率的理论阈值为 `floor((HP-1)/倍率)+1`，实现用真实JS乘法/ceil搜索校验，避免浮点边界误差。例如HP500、抵抗0.5时等效生命为999（不是简单除法得到的1000）；倍率1时等效生命恰为真实HP。属性免疫不画无穷点，而明确说明无法击倒。

横轴保留实际防御资质，必要时向左扩展采样范围；不会为了落在80–200内伪造坐标。属性折算不冒充防御个体/性格折算：仅能与相同攻防配置的参考曲线比较；目标与参考线配置不匹配时在提示中说明。曲线每2资质采样后插值，严格生存判定仍来自实际配置的逐步取整伤害，不使用像素交点判定。

纵轴只选10/20/25/50间距，按数据最大值与绘图区高度选择更细刻度，保留4%上边距。不靠自动跳过数字伪装网格间距；最多501刻度，极端范围/非有限值暂停绘图并提示，不篡改数据或偷偷改成100/200。窗口化画布上限520布局像素；真正最大化由 `/api/window/state` 经 `AppPreferences.getWindowState()` / `isMaximized()` 和 `appwindowstatechange` 驱动，解除上限填满剩余空间，同时保留收藏工具与头像行。异步旧状态不覆盖新状态，不按宽度推断最大化。过矮窗口仍可滚动。

收藏居中，眼睛按钮只控制图上头像，不影响列表或右键取消规则。常驻的等效生命解释已删除，精度/配置差异仍在提示里。图例改为“攻：✓个体&×性格 / 防：✓个体&×性格”，负性格明确标“负性格”；启用标记与伤害过程统一为✓，不是数学根号。

```text
node --test tests/*.test.js scripts/tests/*.test.js
node scripts/audit_skill_sources.js

```

```text
playwright-cli run-code --filename=tests/damage-chart.browser.js
```

该测试会操作浏览器自己的 localStorage，不能在用户日常使用的浏览器配置中运行。

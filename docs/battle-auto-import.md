# 实时导入与手动扫描补录

## 用户选择的方案C

- 实时通道：用户连接已运行的本机RKPP中继后，Wiki持续接收并组装战斗；收到对应的正式结算通知后才纳入战报。
- 归档通道：只在用户点击“扫描采集记录”并明确开始扫描时读取所选归档。
- **启动、打开页面、重连、刷新状态均不自动扫描目录。**保存的目录仅用于下次打开扫描框。
- Wiki不安装驱动、不启动抓包、不操作游戏，也不请求在线历史战绩。未采到且没有归档的信息无法恢复。

## 手动扫描

第一次选择本机RKPP根目录、runs目录、单次运行目录或opencode_summary.csv；成功扫描后记住路径。扫描读取仅限该范围内的同名汇总CSV，不读密钥、原始抓包、decoded_packets或采集日志。目录深度最多2，链接/UNC/设备/遍历路径拒绝；文件、行数、体积、行大小和时间有界，超限要求缩小选择范围。

扫描结果区分新增、更新、已存在、未结束及正常忽略。未完成CSV尾行和未结算战斗不会被当成完成记录。先解析、校验全部有界候选，再经原有事务导入，解析失败不保存前半批。关闭弹窗不取消已经提交的扫描，窗口关闭仍等待写入完成。

只在成功新增或更新时刷新列表/统计；原筛选保留，筛选隐藏新记录时提示检查条件。无变化重扫不触发重复统计计算。

## 实时组装与身份

实时和CSV使用同一个有状态组装器，但每个连接/每个文件独立，不能拼接无关运行。正式开场与结算的战斗ID必须相同；离线、换一场、预计时间到、预播结算或is_battle_finished字段都不能替代正式结算。

RKPP的uint64战斗ID在协议边界无损转换为十进制字符串，不经过JavaScript浮点数。普通规范化JSON的安全数值限制不放宽。仅主执行通道计动作，预播及PvP表现重放不多算；事件键取战斗/回合/序号/执行序号/分支等身份，不取CSV行号、账号或IP。

普通技能只使用明确的运行时ID→配置ID字段对，再通过固定审阅的配置ID→本地ID表映射。表源为已校验SHA256的固定版本SKILL_CONF，运行时不联网、按名字重找或对ID做除法。没有明确绑定的技能保留原协议ID，不冒充已知主技能。聚能保持系统行动；被打断的系统行动不带伤害/能量效果量。

初始敌方阵容可用同次开场others.pets与已知敌方首发实例的唯一重叠、与我方的不相交关系确认，不通过账号匹配，也不从最终首领形态倒推。后期额外实例不混进初始六只。直接我方个体/性格/技能槽保留，未知敌方配置不补0；动作覆盖仍不因有结算而自动升级完整。

## 去重与安全

相同战斗重复扫描不会新增第二场。相同live来源的互补信息允许补齐缺失值，但已有值冲突拒绝，不能改写阶段、顺序或既有事实。另一旧来源已保存的战斗保留原始JSON，不被本轮转换重写。

扫描POST必须携带打开扫描框时获得的服务会话令牌；令牌只保存在内存，不写URL/配置/日志。沿用本机和同源限制。状态区分收到消息、正常忽略、等待结算、实际写入和解析失败；收到消息不等于导入成功。所有错误均不回显原始消息、账号、密钥或IP。

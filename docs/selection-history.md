# 精灵选择与历史顺序

## 历史栏

伤害页历史头像的左键仍选择攻击方、右键仍选择防守方，中键收藏行为不变。历史来源通过独立的selection source传入，不调用MRU插队、保存或重绘历史列表；更新攻守标记和正常的角色配置/技能/特性状态，并独立更新速度页同速首领组合的显示选择。后者不是历史排序写入。

普通搜索、进化家族候选、收藏和编队选择保留原先历史行为：按精灵ID去重、最近选中置前、最多16个、木桩不入历史。历史再选不等同于主动左键点击技能，不清空技能累计或特殊输入。

## 普通精灵的速度展示优先级

伤害页搜索确认、现有完整名称自动选择，以及历史/收藏/编队快捷头像左键选攻击方、右键选防守方，共用独立的速度展示优先记录。落陨星兔等普通精灵由任一入口选中，速度行排序效果相同；快捷历史列表的DOM、顺序和原存储不因历史点击改变。

- [独立优先记录](<../js/damage-speed-priority.js>)保存到已有共享配置`rk_damage_view.speedPriority`，最多16个去重的正整数稳定ID，木桩不计入。只patch该字段，技能快照和其他设置保留。
- 没有有效新记录时只读旧伤害历史作为兼容；首次主动选择才复制初始顺序、将所选ID置前并保存，不做启动迁移。已有有效空数组是明确的空记录。
- 速度页原优先级原则不变：当前速度页有效查询优先，其后为这份伤害选择记录，再后为速度页原记录。只排序已有合资格头像，不改变筛选、首领/高级显隐、等级或数值；不会因普通精灵选择改掉火神/烈火战神的成员选择。
- 清空查询、切页和重启保留已存记录；中键/拖拽收藏、程序恢复、战报自动快照不写新记录。正常快捷选择退出战报后按本次主动选择更新。
- 共用原UserConfig即时草稿、失败重试和关闭flush。静态回退也只合并该字段，不以旧快照覆盖技能；读取不清理旧记录。

## 已选候选框再次展开

公共精灵候选框记录明确选中的稳定ID。再次点击（包括已聚焦时），或关闭后按方向键，显示该条目显式`evolution_members`的其余可选精灵；独立的首领化/普通来源以短标签另外显示。

- 保留当前条目成员顺序，不按父链、数组邻接、同名、同dex或`evolution_chain_name`推导家族，不补对称/传递成员。
- 首领与普通来源只用`leader_of_id`配对。成员仅自身或明确空数组时不借旧父边补候选。
- 最终仍执行原页面的hidden与filter规则并排除当前ID；缺失ID不生成虚构精灵，重复ID不重复展示。
- 输入文字改变后恢复原来的关键词/形态/进化名称搜索，普通精灵搜索不截断到10项。
- 开关候选不触发角色选择或历史改写；实际选中候选才走原回调。
- `setValue(value, monster)`明确更新选中身份；仅回写相同标签可保留既有ID，但不能据同名文字猜新ID。
- 自定义技能搜索不加入进化功能。已选后由原业务清空输入的添加型控件，仍保留原清空行为。
- 保留Escape、方向键、Enter、输入法导航保护、滚动/缩放定位与离页清理。

测试：`selection-search.test.js`、`selection-history.test.js`、`selection-history.browser.js`。浏览器在隔离配置验证历史DOM顺序、角色及百分比/技能记录恢复、黑猫进化链、普通搜索完整性与速度页共用候选框。
